# Optional command-backed ready reports

An operator may set `executor.verify` to a test/check command appropriate for the repository. Empty is the default and preserves existing behaviour. Configured workers receive `orchestrator_verify` with no arguments: the model cannot supply commands, exit codes or a claimed test result. The host runs the operator's command through the worker subprocess runtime and existing command gate, with a five-minute bound. Use the current platform's shell syntax, as with `executor.prepare`.

Only a zero exit result against unchanged code and request records a receipt. `orchestrator_report(state=ready)` requires a matching receipt. The fingerprint covers the assignment, mandate, request inputs, verification configuration, Git HEAD, filenames and hashes of tracked/non-ignored untracked files. Edits, deletions, commits, configuration changes and new requirements invalidate it. Delivery/read timestamps do not. A failing run cannot create a passing receipt. Reusing a persisted matching receipt does not rerun tests.

Ignored files (normally build artifacts/dependencies), filesystem metadata and external services are outside the fingerprint. A workspace with over 10000 included files, or a command whose output exceeds the worker capture limit, is refused instead of accepting a partial snapshot. This is not a sandbox against a malicious worker, an atomic filesystem lock or an independent semantic acceptance test. Zero exit means the configured command passed; operators still need meaningful tests and review. Test commands should not mutate included source files. No test output or credential is persisted in the receipt. No PRD approval or automatic merge is added.
